TPAP devices

These devices answered discovery, but currently advertise TPAP encryption, which python-kasa 0.11.0.1 and 0.12.0 do not support. Some firmware can switch to a supported local protocol when Third-Party Compatibility is enabled.

KP125M Matter plugs: check both requirements

  1. Enable Third-Party Compatibility in the Kasa app under Me → Settings, or in the Tapo app under Me → Third-Party Services.
  2. Set TPLINK_USERNAME and TPLINK_PASSWORD to your TP-Link account credentials in KasaBuena's repository-root .env. If the file is missing, create it from .env.example first; cloning the repository does not include your private .env.
  3. Recreate the container with docker compose up -d --force-recreate kasabuena to load changed credentials, or restart the API for a local run. Then rescan.

If the result changes from unsupported to auth_failed, the protocol blocker has cleared but authentication still needs attention. Check that credentials are loaded and accepted. A working power strip does not mean the individual plugs have the same requirements. KasaBuena uses local Kasa control, not Matter pairing.

Compatibility depends on firmware and model. See TP-Link's Third-Party Compatibility guidance for the setting's purpose and tradeoffs. Changing credentials alone does not add TPAP support.
